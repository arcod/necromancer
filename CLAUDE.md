Guidance for Claude when working in this repository.

## Project

**Necromancer** is an RTS/survival game built in **Unity** (C#), edited in VS Code, hosted on GitHub (`arcod/necromancer`).

### Repo layout

| Folder | What it is |
|---|---|
| `DOTS_Scratch/` | **Learning sandbox.** A throwaway Unity project for building a bare-bones DOTS RTS and learning Unity. Mistakes are fine here; don't over-engineer. |
| *(not created yet)* | The real Necromancer Unity project. Lessons from the scratch project get rebuilt here cleanly. |
| `docs/` | Design docs (below). |

`DOTS_Scratch` uses Unity **6000.0.33f1**, URP, Entities **1.3.x**, Unity Physics, and the new **Input System** package. Scripts go in `DOTS_Scratch/Assets/Scripts/`; the main scene is `Assets/GameScene.unity` with entities in the SubScene `Assets/GameScene/EntitiesSubscene.unity`.

## Working rules

- **Use the nomenclature in GAME_MECHANICS.md.** Class names, component names, variables, and comments should use the same terms the user defined there. If a needed term isn't defined, ask or propose one rather than inventing silently.
- **Stay within the current milestone** in ROADMAP.md. Don't build ahead of it unless asked.
- **Follow ARCHITECTURE.md guidelines**, e.g. keep the file count low.
- If a request conflicts with one of the docs, point out the conflict before proceeding.
- When a mechanic is implemented or changed, offer to update GAME_MECHANICS.md so it stays accurate.

## DOTS / ECS

The game uses **DOTS** (Entities, Jobs, Burst) so it can handle very large enemy hordes (think *They Are Billions*).

- Gameplay that scales with unit count (movement, targeting, combat, death) belongs in ECS: `IComponentData` structs for data, `ISystem` for logic, Burst-compiled where possible.
- Author entities with GameObjects + `Baker` classes in SubScenes; don't use MonoBehaviours for per-unit runtime logic.
- MonoBehaviours are fine for things that exist once: UI, camera, input, menus.
- Anything rendered as an entity needs an SRP Batcher–compatible material (URP Lit, Simple Lit, Unlit, or a Shader Graph shader). `Universal Render Pipeline/Terrain/Lit` and legacy built-in shaders won't render under Entities Graphics.
- The user is new to Unity — briefly explain DOTS concepts when introducing them.

## Unity-specific notes

- Within a Unity project folder, only edit files under `Assets/`, `Packages/manifest.json`, and `ProjectSettings/` deliberately. Never edit `Library/`, `Temp/`, `Obj/`, `Logs/`, or `UserSettings/` — they are generated by Unity.
- Every asset has a matching `.meta` file containing its GUID. When creating, moving, renaming, or deleting a file under `Assets/`, handle its `.meta` file too (or let Unity regenerate it for new files). Never change a GUID in an existing `.meta` file — it breaks references.
- Scenes (`.unity`) and prefabs (`.prefab`) are YAML. Avoid hand-editing them except for small, well-understood changes; prefer doing that work in C# or asking the user to make it in the Editor.
- Claude cannot run the Unity Editor or play the game. After code changes, tell the user what to check in the Editor.
- C# style: standard Unity/C# conventions — `PascalCase` for types, methods, and public members; `camelCase` for locals and private fields; a `MonoBehaviour` must live in a file named after it. To keep the file count low, a feature's ECS components, authoring/baker, and systems can share one file (named after its authoring MonoBehaviour).
